## 1. 项目概述

### 1.1 项目定位

**Chat2API** 是一款基于 Electron 的桌面端 AI 服务统一管理工具。它通过驱动各大模型的**官方 Web UI 接口**，以零 API 费用成本接入主流大模型，并在本地启动一个 **OpenAI 兼容的 HTTP 代理服务**，使 Cline、Roo-Code、Cherry Studio、openclaw 等任意 OpenAI 兼容客户端均可直接调用。

### 1.2 核心价值

| 能力 | 说明 |
|------|------|
| 统一接入 | 一个本地端口（默认 `127.0.0.1:8080`）对接多个 AI 服务商 |
| 零成本 | 复用官方 Web 端会话，无需购买商业 API Key |
| 兼容性强 | 支持 OpenAI Chat Completions、Anthropic Messages API |
| 工具调用 | 通过提示词工程为不支持原生 Function Calling 的模型注入工具能力 |
| 多账户负载均衡 | 支持轮询、优先填充、故障转移等策略 |
| 可视化管理 | 仪表盘、日志、模型映射、会话管理一应俱全 |

### 1.3 功能清单

- **OpenAI 兼容 API**：`/v1/chat/completions`、`/v1/completions`、`/v1/models`
- **Anthropic 兼容 API**：`/v1/messages`
- **多服务商**：DeepSeek、GLM、Kimi、MiniMax、Mimo、Perplexity、Qwen、Qwen AI、Z.ai
- **上下文管理**：滑动窗口、Token 限制、摘要压缩
- **工具调用**：Bracket / XML / Anthropic / JSON 多格式解析，兼容 Cherry Studio、Kilo Code
- **模型映射**：通配符、首选服务商/账户
- **自定义 Header**：`X-Web-Search`、`X-Reasoning-Effort`、`X-Deep-Research`
- **API Key 管理**：本地代理访问鉴权
- **请求日志**：完整请求/响应记录，便于调试
- **管理 API**：`/v0/management/*` 远程配置
- **系统托盘**：快速启停代理、查看状态
- **内置聊天客户端**：应用内直接对话
- **多语言**：中文 / 英文
- **主题**：深色 / 浅色

## 3. 整体架构

### 3.1 分层架构

```
用户 / 外部客户端
        │
        ▼
┌───────────────────┐
│  OpenAI 兼容 API   │  ← Koa ProxyServer
│  /v1/chat/...     │
└────────┬──────────┘
         │
    ┌────┴────┐
    ▼         ▼
ModelMapper  LoadBalancer
    │         │
    └────┬────┘
         ▼
  RequestForwarder
         │
    ┌────┴────────────────┐
    ▼                     ▼
Provider Adapter    通用 Axios 转发
(DeepSeek/GLM/...)   (自定义服务商)
    │
    ▼
上游 Web API
```

### 3.2 数据流概览

1. **外部客户端** → `POST /v1/chat/completions` → 代理服务
2. **模型映射** → 解析请求模型到实际模型名
3. **负载均衡** → 选择可用账户
4. **请求转发** → 上下文裁剪 → 工具提示词注入 → 调用 Provider Adapter
5. **流式/非流式响应** → SSE 转换 → 工具调用解析 → 返回客户端
6. **日志记录** → 写入 electron-store，推送至 UI

## 6. 代理服务详解

代理服务是本项目的**核心引擎**，基于 Koa 实现，默认监听 `127.0.0.1:8080`。

### 6.1 ProxyServer — `src/main/proxy/server.ts`

**职责：** 创建和管理 HTTP 代理服务器。

```typescript
class ProxyServer {
  async start(port?: number, host?: string): Promise<boolean>
  async stop(): Promise<boolean>
  async restart(port?: number, host?: string): Promise<boolean>
  isRunning(): boolean
  getPort(): number
  getStatistics()
  getStatus()
  resetStatistics(): void
}
export const proxyServer = new ProxyServer()
```

**中间件链：**

1. **CORS** — 允许跨域，`OPTIONS` 返回 204
2. **bodyParser** — JSON/表单/text 上限 50MB
3. **API Key 鉴权** — 若 `config.enableApiKey` 为 true，校验 `Authorization: Bearer`、`X-API-Key` 或 `api_key` 查询参数；`/health`、`/stats`、`/v0/management/*` 跳过
4. **请求日志** — 记录请求方法与路径
5. **路由** — OpenAI 路由 + 管理 API 路由

**公开端点（无需 API Key）：**

| 路径 | 说明 |
|------|------|
| `GET /` | 服务信息 |
| `GET /health` | 健康检查 |
| `GET /stats` | 统计信息 |

### 6.2 LoadBalancer — `src/main/proxy/loadbalancer.ts`

**职责：** 根据策略从多个账户中选择可用账户。

```typescript
class LoadBalancer {
  markAccountFailed(accountId: string): void
  clearAccountFailure(accountId: string): void
  selectAccount(
    model: string,
    strategy?: LoadBalanceStrategy,      // 'round-robin' | 'fill-first' | 'failover'
    preferredProviderId?: string,
    preferredAccountId?: string
  ): AccountSelection | null
  resetRoundRobinIndex(): void
  getAvailableAccountCount(model, providerId?): number
  getAvailableModels(): string[]
}
```

**账户筛选条件：**
- 服务商已启用
- 账户状态为 `active`
- 账户支持请求的模型（含有效模型列表）
- 未超过每日请求/Token 限额
- 未处于故障冷却期（连续失败 3 次 → 冷却 60 秒）

**策略说明：**

| 策略 | 行为 |
|------|------|
| `round-robin` | 按模型维度轮询可用账户 |
| `fill-first` | 优先使用第一个可用账户直到限额 |
| `failover` | 排除故障账户，选第一个可用 |

### 6.4 RequestForwarder — `src/main/proxy/forwarder.ts`

**职责：** 将 OpenAI 格式请求转换为各服务商 API 调用，是整个转发链路的枢纽。

```typescript
class RequestForwarder {
  async forwardChatCompletion(
    request: ChatCompletionRequest,
    account: Account,
    provider: Provider,
    actualModel: string,
    context: ProxyContext
  ): Promise<ForwardResult>

  async forwardToUrl(url, method, headers, body, isStream?): Promise<ForwardResult>
}
export const requestForwarder = new RequestForwarder()
```

**核心私有方法：**

| 方法 | 作用 |
|------|------|
| `transformRequestForPromptToolUse()` | 对不支持原生 Function Calling 的模型，委托 `PromptInjectionService` 注入工具提示词 |
| `parseToolCallsFromContent()` | 从响应文本解析工具调用（Bracket/XML/Anthropic/JSON） |
| `applyToolCallsToResponse()` | 将解析出的 tool_calls 写入 OpenAI 格式响应 |
| `doForward()` | 根据 `provider.id` 分发到对应 Adapter 或通用 Axios 转发 |
| `buildHeaders()` / `buildRequestBody()` | 自定义服务商的通用请求构建 |

**转发前处理流水线：**

```
原始请求
  → 上下文管理 (ContextManagementService)
  → 工具提示词注入 (PromptInjectionService)
  → MCP 工具协议转换（Cherry Studio 等）
  → Provider Adapter 或通用转发
  → 响应工具调用解析
  → 返回 ForwardResult { stream?, body?, skipTransform? }
```

**重试机制：** 根据 `config.retryCount` 和 `retryDelay` 在失败时自动重试。

### 6.11 路由模块 — `src/main/proxy/routes/`

#### chat.ts — `POST /v1/chat/completions`

**处理流程：**

1. 解析请求体，校验 `model` 和 `messages`
2. 合并自定义 Header：`X-Web-Search` → `webSearch`，`X-Reasoning-Effort` → `reasoning_effort`，`X-Deep-Research` → `deepResearch`
3. `modelMapper.getPreferredProvider/Account()` 获取映射
4. `loadBalancer.selectAccount()` 选择账户
5. `requestForwarder.forwardChatCompletion()` 转发
6. 流式：`skipTransform` 时直接 pipe；否则 `streamHandler.createTransformStream()`
7. 非流式：可选 `transformResponseToAnthropic()` 转换工具格式
8. 记录请求日志、更新账户用量、标记失败账户

**辅助函数：**

| 函数 | 作用 |

| `generateRequestId()` | 生成 `chatcmpl-xxx` 格式 ID |
| `getClientIP(ctx)` | 从 `x-real-ip` / `x-forwarded-for` 提取客户端 IP |
| `extractUserInput(messages)` | 提取最后一条用户消息内容（用于日志） |

#### messages.ts — `POST /v1/messages`

## 7. OAuth 认证体系

### 7.1 架构

```
Renderer (LoginDialog)
    │ IPC: oauth:startLogin / startInAppLogin / loginWithToken
    ▼
OAuthManager (oauth/manager.ts)
    │
    ├── 外部浏览器模式 → BaseOAuthAdapter.startLogin()
    │       └── 回调服务器 :8311 或手动复制 Token
    │
    └── 应用内登录 → InAppLoginManager (inAppLogin.ts)
            └── Electron BrowserWindow + Cookie/Header 拦截
                    └── tokenExtractionConfig 提取凭证
    │
    ▼
adapter.validateToken() → OAuthResult { credentials }
    │
    ▼
Renderer → accounts:add → StoreManager（加密存储）
```

## 12. 请求处理全流程

以 `POST /v1/chat/completions` 为例：

```
1. 客户端请求
   Authorization: Bearer sk-xxx
   POST /v1/chat/completions { model, messages, stream, tools }

2. ProxyServer 中间件
   ├── CORS 处理
   ├── bodyParser 解析（≤50MB）
   └── API Key 校验（若 enableApiKey）

3. chat.ts 路由处理
   ├── 校验 model + messages
   ├── 合并 X-Web-Search 等 Header
   ├── modelMapper → preferredProvider / preferredAccount
   └── loadBalancer.selectAccount(model, strategy)
       ├── 过滤：启用服务商、active 账户、模型支持、未超限额
       └── 返回 { account, provider, actualModel }

4. requestForwarder.forwardChatCompletion()
   ├── ContextManagementService.process() → 裁剪/摘要历史
   ├── PromptInjectionService.process() → 注入工具提示词
   ├── doForward() → Provider Adapter
   │   ├── DeepSeekAdapter.chatCompletion()
   │   ├── KimiAdapter.chatCompletion()
   │   └── ... 或通用 Axios 转发
   └── 重试（retryCount 次）

5. 响应处理
   ├── stream=true + skipTransform → 直接 pipe SSE
   ├── stream=true → streamHandler.createTransformStream()
   │   └── 解析 [function_calls] → tool_calls
   └── stream=false → JSON + applyToolCallsToResponse()

6. 后处理
   ├── proxyStatusManager.recordRequestSuccess/Failure()
   ├── storeManager.addRequestLog()
   ├── 更新 account 用量计数
   └── 4xx 错误时 loadBalancer.markAccountFailed()
```

1. 在 `src/renderer/src/pages/` 创建页面组件
2. 在 `App.tsx` 添加懒加载路由
3. 在 `Sidebar.tsx` 添加导航项
4. 如需状态管理，在 `stores/` 创建 Zustand store
5. 如需 IPC，在 `preload/index.ts` 和 `types/electron.d.ts` 添加 API

### 15.4 调试技巧

| 场景 | 方法 |
|------|------|
| 主进程日志 | 开发模式自动打开 DevTools；或查看终端输出 |
| 代理请求 | 访问 Logs 页面查看 RequestLogDetail |
| IPC 通信 | DevTools Console 调用 `window.electronAPI.*` |
| 代理 API | `curl http://127.0.0.1:8080/health` |
| 存储数据 | 查看 `~/.chat2api/data.json` |

### 15.5 代码规范

- TypeScript 严格模式
- 函数式组件 + Hooks
- 接口优先于 type
- 避免 enum，使用 map/union
- 主进程与渲染进程通过 IPC 通信，不直接引用
- 新增服务商遵循 Adapter 模式
